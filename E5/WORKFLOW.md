# A08 E5—E6 联合分工与流程

E5、E6 统一安排但属于两次独立作业。本文件供后续 E6 引用，目前仅建立 E5 骨架。

## 分支和协作

共同整合分支 `a08/e5-e6` 起于 `827b1cf`（PR #4 合并后的 main）。
`e5-reference-import` 已合并，不需再次合并。组长在正式实验前公布包含资源适配的完整基准 SHA。
分别记录运行代码、镜像构建代码和后续报告提交版本，不能只用分支名对照版本。

E4 使用共同分支直接提交；本次整理手册提供个人贡献分支和 PR 流程。
保留现有 `student/<学号>/e5-e7` 等个人分支，同步共同版本后提交个人贡献，
个人 PR 经审阅合入 `a08/e5-e6`，阶段验收后由组长提交整合 PR 至 main。
PR 以组分支为目标属于本组安排，课程手册示例以 main 为目标；平台另有要求时再对齐。
已有分支和未提交修改先检查、保存，不覆盖或强制推送；不配置共享 root 的全局作者或认证。
成员需具备本人 GitHub 仓库写入权限。

## 顺序与审阅

1. 组长审阅骨架和资源适配，公布统一运行 SHA（目前待公布）。
2. 各人恢复认证、同步代码，核对身份、SHA、工作区，依次构建个人镜像。
3. 各自执行 E5，记录命令、日志、真实 PID/行号及输入声明。
4. 按分工专项审阅。个人记录和审阅由本人维护，共同报告及导航由组长整合，避免覆盖。
5. 组长核对四人证据，至少选两人的同 SHA 结论对照；PID/行号无需相同。
   这是延续 E4 的小组质量检查，不冒充新增加的教师要求。
6. 个人贡献 PR 审阅、整合，核对 E5 提交清单，下载归档，按平台要求独立上传 E5。
7. 接续 E6 自动检测、修复复检及新增测试，另建报告与提交包，不混作 E5 成果。

原始 work/ 不提交 Git；记录服务器和电脑备份位置。区分源码审阅、本人实测与他人证据核对，
预期结果和 AI 推断不能写成已执行结果。
