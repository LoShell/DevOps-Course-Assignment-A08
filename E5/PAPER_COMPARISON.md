# E5 与 BuildChecker 论文的对应及复现边界

整理人：刘馨雅（241250088）；日期：2026-11-01；状态：已审阅。

原文：Jun Lyu 等，*Detecting Build Dependency Errors by Dynamic Analysis of Build
Execution against Declaration*。本次核对本地课程 PDF `_TSE__BuildChecker.pdf`，
PDF 共 18 页，主要依据第 4–6 页的第 4 节、图 2 及算法 1/2，
实验规模依据第 1–2 页和第 5 节。页码按本地 PDF 的页序。

## 1. 复现目标

论文把实际构建执行和用户声明关联到构建目标，再检查差异以发现缺失依赖和冗余依赖。


## 2. 机制对应

| 原文机制及位置 | 本次 E5 做法 | 实测依据与范围 |
| --- | --- | --- |
| 从完整 clean build 获取执行；4.1、图 2，第 4 页 | 在独立副本 make clean 后执行真实 make -p app | runner/command.json 保存实际命令，包含编译和链接作业 |
| ptrace 追踪文件操作并分析进程与文件关系；4.2.1，第 4–5 页 | 用 strace -ff 跟踪文件与进程系统调用，以成功打开和父子关系人工还原作业 | 088 的 cc1（16）读取输入，as（17）生成 main.o，同属 cc（15） |
| 从 GNU Make 内部数据库取得声明 | 保留 make -p app 完整输出，人工定位目标与依赖 | make-db.txt:1061 为 main.o，609 为 app |
| 执行和声明按目标关联；4.2.3，第 6 页 | 整理 main.o、app 的实际/声明依赖表 | 多个编译子进程合并到同一作业 |
| 逐目标比较实际/声明并过滤项目外依赖；4.3、算法 2，第 6 页 | 人工计算 MD=实际减声明，RD=声明减实际 | main.o 缺 config.h、多声明 unused.h；app 一致 |

## 3. 实验结果

组长原始包已经只读核对：输入副本、7 份 trace、Make 数据库、runner、
程序输出和 source-commit 均可读取，关键行与人工结论吻合。
其余三位成员已回报同基准得到相同结论，原始包和专项报告尚待小组抽查。


## 4. 与原文的差异

- **实现方式**：论文自动建立执行—声明模型并检测错误；本次使用教学入口采集，由人工完成进程归属和依赖判定。
- **样例规模**：论文评估 30 个开源项目；本次四人复现同一个 C/Make 样例，输入为 main.c、config.h、unused.h 和 Makefile，输出 main.o 与 app。
- **验证重点**：论文评估检测效果与检测时间；本次核对完整原始证据、精确 MD/RD、15 项服务测试及程序输出。
- **运行环境**：本组使用课程统一配发的 2 GiB ECS，在个人容器镜像中完成构建和跟踪。

## 5. 可得结论

在本次项目边界和构建配置下，证据支持 main.o 的 MD=config.h、RD=unused.h，
app 的项目依赖一致。结果展示了论文的执行—声明对照思路。
