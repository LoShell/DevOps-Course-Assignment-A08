# E8—E9 协作流程

沿用 E5—E7 的共同分支与个人 PR 模式。组长刘馨雅 241250088，成员邱莉扉 241250097、范从钰 241250071、叶原原 241250076。

## 分支与版本

- 共同分支：a08/e8-e9，从已完成 E7 的 main 起步。
- 个人分支：a08/<学号>/e8-e9，从组长发布的共同基线完整 SHA 创建。
- 个人 PR：base 为 a08/e8-e9；compare 为本人分支。
- 集成 PR：base 为 main；compare 为 a08/e8-e9，待真实验收后创建。
- 共同基线 SHA：待框架提交后发布。每人记录实际运行 SHA，后续文档提交不替代运行版本。

框架提交与服务器验证分开记录。组长先在服务器验证共同基线，再发布成功状态和证据；组员之后依次构建、运行基线与个人扩展。当前没有服务器成功结论。

## 文件归属

每人维护 labs/e8e10/test_student_<学号>.py、E8/records/<学号>.md、E9/records/<学号>.md、两阶段验收 CSV、两阶段对应 review 专项，以及 docs/students/<学号>/e8-e10 下个人报告、ADR、AI_USAGE。

个人测试独立成文件，避免多人改 test_profile.py。需要修改 lab.py 时，先在专项记录中说明问题、负责人和影响；组长协调后再改，其他成员不同时修改同一函数。E8/E9 共同报告、导航、分工表与 CI 由组长整合。个人修改提交前固定代码 SHA，使用新 OUT 复验受影响阶段。

Git 保存代码、报告、结果摘要和证据索引；work 原始证据归档下载。不得把尚未运行的计划写成通过结果。

## 收尾

审阅每人独立预期、实际结果、SHA/镜像/OUT、证据归档及 PR；共同分支合入四人贡献后在服务器做集成验证。核对原 E7 检查和新 e8e10-quality-gate，下载 Actions artifact，再由组长整理 E8、E9 独立交付材料。远端发布、服务器实验和 CI 状态按实际补录。
