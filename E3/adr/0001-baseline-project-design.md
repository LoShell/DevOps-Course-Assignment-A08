# ADR-0001：E3 基线项目设计

- 状态：Accepted
- 日期：2026-09-30

## 背景

E3 要求 A08 准备固定 MD/RD 和 C0/C1/C2 测试基线，并保留可复现证据。课件
中的实验包和项目仅为示例，助教确认需要小组自行构造。B08 表示继续沿用其 E2
示例的项目语义，但 E2 材料中的 URL、SHA 和构建产物均为静态占位内容。

## 决定

1. 自建一个 Linux C + GNU Make 小型项目，避免第三方运行时依赖。
2. 使用 `ubuntu:24.04` 作为容器基线，并安装 `build-essential` 和
   `ca-certificates`。
3. 使用 `src/`、`include/`、`build/` 和 `bin/demo`，尽量延续 B08 E2 示例
   的路径语义。
4. 固定 MD/RD 使用独立副本；C0/C1/C2 使用另一份项目的连续提交历史。
5. C0、C1、C2 分别用 `e3-c0`、`e3-c1`、`e3-c2` 注释标签固定。
6. 编译器版本和 `configuration_id` 以服务器真实输出为准，不预填 GCC 版本。

## 理由

小型自建项目能精确控制依赖读取、Makefile 声明和编译命令变化，也能保证每条
oracle 都可人工解释。将固定 MD/RD 与增量链分开，可以避免为了同时制造 RD
而破坏 C0“依赖正确”的前提。

## 影响

- 需要提交项目源码、Makefile、Dockerfile、复现脚本和实验日志。
- E3 结果只能证明测试基线可复现，不代表 BuildChecker 或 EChecker 已实现。
- B08 可以在后续阶段消费 A08 的真实输入，但 A08 当前工作不依赖 B08 的输出。
